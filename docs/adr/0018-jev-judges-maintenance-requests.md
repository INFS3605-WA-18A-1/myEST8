# Jev judges each Maintenance Request once; code writes the profile read

A Tenant's profile should say, in one sentence, what their history adds up to: they report often and it's mostly small, they report rarely and it's usually real, or several repairs may have come from them. Counting Tickets cannot say which requests were minor, or which ones the Tenant's own account suggests they caused. Those two questions are judgments. The sentence and the chips under it are not.

**Jev scores each request, once.** The first time a Tenant's profile opens, any of their Maintenance Requests from the last twelve months that have no judgment yet — open, closed, rejected, and Urgent Repairs — go to Jev (TypeSafe's System One model) in one call, at most twenty of them. The call asks two questions over the same state: a Score, "How minor is this maintenance request?", on three levels from cosmetic or trivial up to a safety, security or habitability problem; and a Noul, "Was the damage likely caused by the Tenant's misuse or negligence rather than wear, age or a defect?" The Tenant's description and summary are untrusted data in the state, never copied into an instruction. `src/adapters/jev-request-judge.ts` holds the questions. `JEV_API_URL` and `JEV_API_KEY` configure it, as for classification ([ADR 0011](0011-jev-classifies-haiku-composes.md)) and job fit ([ADR 0016](0016-jev-judges-job-fit.md)).

**The judgment is stored and not asked again.** Each answer lands in `issue_judgments`: `minor` (the Score flipped onto 0–1, so 1 is the most minor) and `tenant_caused` (the Noul, already 0–1), with the model name. A later opening of the profile reads the row. The page waits at most eight seconds. If the call fails or times out, one line goes to stderr with none of the Tenant's words, nothing new is stored, and the read is built from the counts code can already see. A hosted app with no Jev URL does that from the start. The demo, with no URL, uses the same keyword stand-in as the other Jev calls.

**Code owns the words.** `src/profile-reads.ts` turns the year's requests and any stored judgments into one sentence and a few chips. A request counts as minor at 0.6, and as possibly Tenant-caused at 0.7. The sentence follows those counts: five or more in the year and mostly minor is "Reports often, mostly small things"; two or more possibly caused is "Several repairs may have been caused by the Tenant"; two or fewer, none rejected and none possibly caused, is "Reports rarely, and it's usually real". The chips say "possibly" and "may have been". They never accuse. A Property Owner, Building Manager or Tradie has no model in their read: theirs is the same shape, from approvals, Common Area messages, Jobs, Quotes and visits.

We chose one stored judgment per request over judging on every page view, because the request does not change and a profile must not wait on a model. We chose code for the sentence over asking Jev to write it, because the wording is a rule the Agency can read, and a model must not be the thing that says a Tenant caused the damage.
